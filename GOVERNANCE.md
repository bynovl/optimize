# License Evolution Governance

Our [license](./LICENSE) reflects what we believe to be forward progress in the sustainability of open source projects and its maintainers. It's inspired by the [FairCode](https://faircode.io/) model with some provisions in response to AI abuse. With support from legal guidance and community input as the project and technology evolves, the license terms may change. By being transparent from day one and allowing you to actively participate in those changes is vital. The following outlines how you can contribute to its progress:

## Principles

1. **Transparency**: All proposals discussed publicly
2. **Fairness**: Balance between project health and user freedom
3. **Predictability**: No surprise changes to existing versions
4. **Reciprocity**: Commercial extractors contribute fairly

---

## Decision Process

1. Proposal submitted as **GitHub Discussion** in the [License RFCs](https://github.com/bynovl/optimize/discussions/categories/rfcs) category
2. **Signal phase** (30 days): Community engagement determines consideration threshold
   - Low engagement → RFC archived with explanation
   - Strong engagement → Proceeds to formal review
3. **Review phase**: Maintainers + contributors + commercial license partners evaluate
4. **Decision**: Result published as final comment with rationale
5. If approved:
   - Discussion converted to GitHub Issue (track implementation)
   - Changes will be made with the next release
6. If denied:
   - Discussion closed with explanation
   - May be reopened if circumstances change

---

## Changes That Require Internal Review

- Removing existing usage rights
- Adding new restrictions
- Changing compensation thresholds
- Altering attribution requirements

---

## Stability Guarantee

**Version Locking**: Published versions never change their license terms. 

- `npm install optimize@1.4.0` → Always BYNOVL-SAL-1.0
- `npm install optimize@latest` → May include new terms

When license changes are approved:
- 30-day advance notice before release
- Applied to whichever release becomes `latest` (major, minor, or patch)
- Older versions remain accessible under original terms

---

## RFC Submission

1. Navigate to [GitHub Discussions > RFCs](https://github.com/bynovl/optimize/discussions/categories/rfcs)
2. **Open the pinned discussion**: "📋 RFC Submission Template" at the top of the category
3. Copy/paste the template from that discussion into your new submission
4. Fill in sections and submit

> ℹ️ The template lives in the pinned discussion for easy updates. Check it for the latest version.
